## 2. 理论复测：12.5/20

| 题目 | 得分 | 当前判断 |
|---|---:|---|
| Pre-Norm 与 Residual | 2.5/3 | 两条公式正确，但未明确指出 identity Residual 主路 |
| SwiGLU Parameter/Activation shape | 3/3 | gate/up/down 权重和主要 Activation shape 正确 |
| `Dmodel % H` 与 Mask 广播 | 0.5/3 | 没有说清拆 Head 的整除条件和从右对齐广播规则 |
| 全 False Mask | 1.5/3 | 知道不存在合法概率分布，缺少 `-inf`、分母为 0 和 NaN 机制 |
| Prefill/no-cache/cached 数据流 | 1/4 | 只写出 cached Query 切片，缺历史重算、Cache 写入/读取/追加 |
| KV Cache bytes | 4/4 | 公式及 512 MiB 计算正确 |

### 已掌握

- 两条 Pre-Norm 公式能够正确写出：

  `h = x + MHA(RMSNorm(x))`

  `y = h + SwiGLU(RMSNorm(h))`

- SwiGLU 权重方向正确：gate/up 为 `[Dff,Dmodel]`，down 为 `[Dmodel,Dff]`。
- KV Cache 公式正确：

  `2 * layers * batch * Hkv * sequence * head_dim * element_size`

- 数值题计算正确：`536,870,912 bytes = 512 MiB`。

### 必须订正

1. `Dmodel % H == 0` 是为了把 `[Dmodel]` 均分为 `[H,Dh]`，其中 `Dh=Dmodel/H`；它与 Mask 广播不是同一约束。
2. Mask 从右向左对齐，对应维必须相等或其中一个为 1；例如 `[Tq,Tk]` 可复用于 `[B,H,Tq,Tk]`。
3. 全 False 行经 Mask 后全部为 `-inf`，没有合法 Key，无法归一化为和为 1 的分布；稳定 Softmax 还可能出现 `-inf - (-inf) = NaN`。
4. Prefill 计算全部 token 的 Q/K/V 并写入 K/V Cache；no-cache Decode 每步重算历史；cached Decode 只用 `[BH,1,Dh]` 的新 Query，但读取并追加 `[BH,Tpast+1,Dh]` 的 K/V。

### 理论能力判断

- 稳定项：公式复现、Linear shape、容量计算。
- 部分掌握：Residual 主路、全屏蔽行结论。
- 薄弱项：shape 约束背后的原因、广播规则、Prefill/Decode 的完整状态变化。
- 结论：当前能做局部计算题，但尚不能稳定地把 Attention 执行过程讲成完整因果链。

## 4. 今日工程实现

### Attention Core Benchmark

计时边界保持为：

`QK^T -> scale -> Mask -> Softmax -> weights@V`

计时区包含 Attention Core，不包含 Embedding、QKV Linear、RMSNorm、FFN、H2D、Tokenizer、网络队列和序列化。

三个 case 已实现：

- `prefill`：`Q/K/V=[BH,T,Dh]`，计算完整输出。
- `decode_no_cache`：执行完整 Attention 后只取最后一个 Query 输出，用作“每步重算历史”的对照组。
- `decode_cached`：`Q=[BH,1,Dh]`、`K/V=[BH,T,Dh]`，模拟读取历史 Cache。

正确性证据：

- 每个 case 的输出 shape 符合当前合同。
- CPU/CUDA JSON 中所有 `output_is_finite` 均为 true。
- 计时前使用 `assert_close` 检查完整 Attention 最后一行与 cached Query 输出一致。
- pytest 只使用小尺寸 smoke，正式网格通过 CLI 运行。

### 公共工具重构

新增 `python/benchmark_utils.py`，集中管理：

- `DTYPE_MAP`
- `validate_timing_config`
- `time_cpu`
- `time_cuda`
- `summarize`
- `save_result`

结构从：

`benchmark_attention -> benchmark_matmul`

调整为：

这消除了 Attention 对 MatMul CLI 文件的错误依赖，并避免两份 timer/statistics/JSON 实现逐渐不一致。

## 6. Observation、Hypothesis 与 Limitation

### Observation

- CPU 上 T 从 128 增至 512（4 倍）时，prefill median 从 0.2570 ms 增至 4.5014 ms，约为 17.5 倍；完整 Attention 呈接近二次增长。
- CPU cached Decode 同期只从 0.0845 ms 增至 0.1148 ms，增长约 1.36 倍。
- CPU 上 cached 相对 no-cache 的 median 加速比约为 4.3 倍（T=128）和 39.7 倍（T=512）。
- CUDA 小尺寸结果不单调：T=512 的 prefill 比 T=128 更快，且 T=512 的 cached Decode 比 no-cache 更慢。

### Hypothesis

- CPU prefill/no-cache 主要受到 `[T,T]` scores、Mask 和 Softmax 的二次工作量影响；cached Decode 将 Query 长度降为 1，因此理论工作量从近似 `O(T^2)` 降为 `O(T)`。
- CUDA 小尺寸工作负载可能被 Kernel launch、调度、实现选择和 GPU 利用率不足主导，单次网格不足以稳定展示复杂度趋势。
- cached Decode 在 GPU 上更像小型 GEMV/窄 GEMM，算术强度和并行度较低，因此减少 FLOPs 不保证在所有小尺寸上立即降低延迟。

### Limitation

- CPU 使用 float32、5/20；CUDA 使用 float16、10/100，协议不同，不能直接计算 CPU/CUDA 加速比。
- 当前只是 Attention Core，不包含 QKV projection、真实 Cache append、H2D、端到端 Decoder 或 Serving 开销。
- 每个网格只有一次实验级运行，没有多轮交替、置信区间或 envelope。
- 尚未结合 Profiler 核对 Kernel、launch gap、同步与内存行为，因此 CUDA 原因仍是假设。

## 7. 当前代码合同缺口

1. `--kv-heads` 已被 CLI 解析，但 `run_attention_case` 仍使用 `heads` 计算 Cache；当前 Hq=Hkv=8 不受影响，GQA/MQA 会产生错误语义。
2. `--layers` 已被 CLI 解析，但 `main()` 没有传给 `run_attention_case()`，运行中仍使用默认 `layers=1`。
3. `kv_cache_bytes` 已计算但没有写入返回结果，JSON 无法核对 Cache 容量。
4. JSON 字段 `cuda_vesion` 拼写错误，应为 `cuda_version`。
5. Attention 使用 `sample_ms`，MatMul 使用 `samples_ms`，公共 schema 尚未统一。
6. Attention JSON 缺少 `timer`、`count/min/mean/max`、`layers` 与 `kv_heads` 等实验上下文。
7. 当前只实现标准 MHA 的实际 K/V Tensor；在真正实现 GQA 前，不应允许 `kv_heads != heads` 后仍声称测得 GQA。
