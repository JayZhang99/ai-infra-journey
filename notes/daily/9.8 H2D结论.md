# 9.8 H2D 五轮实验结论

## Observation

在当前实验协议下：

- chunks=8 的 Pipeline median-of-medians 最低，为 1.5196 ms。
- 因此，chunks=8 是当前三个候选值中的绝对 Pipeline 性能最优值。
- chunks=8 的 Pipeline median 跨轮范围最大，为 0.4805 ms，
  说明它的中位数表现存在一定跨轮波动。
- chunks=32 的 speedup 中位数最高，为 2.058x。
- 但 chunks=32 的绝对 Pipeline MoM 为 2.4618 ms，
  慢于 chunks=8，不能根据 speedup 将其称为绝对性能最优。
- chunks=32 的 p95 跨轮范围达到 4.5934 ms，
  尾延迟稳定性明显弱于 chunks=2 和 chunks=8。

## Hypothesis

- chunks 较小时，单个 chunk 的计算和传输时间较短，
  launch、event 和 Python 调度等固定开销占比可能更高。
- chunks 较大时，虽然相对于相同 chunks 的 sequential 基线
  可以得到更高 speedup，但每个 chunk 太小，可能增加调度开销，
  并降低实际 Pipeline 的绝对性能。
- chunks=8 可能在固定开销和 H2D/Compute overlap 机会之间
  取得了更合适的平衡。

以上内容是根据结果提出的假设，不是现有数据已经证明的原因。

## Next test

1. 保持 dtype 和总字节数不变，增加 chunks=4、16 两个点。
2. 改变总字节数，检查 chunks=8 是否仍然最优。
3. 从 trace 统计 kernel 数、H2D 数、busy union、overlap 和 gap。
4. 重复测试 chunks=32，调查 p95 跨轮波动较大的原因。
5. 固定 GPU 时钟或至少记录温度、功耗和后台负载。

## Limitation

- 当前结果只来自一张 RTX 4070 Ti。
- 只测试了一种 dtype 和一个总数据规模。
- 每个配置只有五轮数据。
- 当前结论只能用于本实验协议，不能推广为通用最优 chunks。
