### 已掌握或明显进步

- 能说明 `eval()` 只切换 Module 行为，不能关闭 Autograd。
- 能说明 `no_grad()` 不阻止 BatchNorm 在 train 模式更新 running stats。
- 能说明连续 backward 不清梯度时会发生梯度累积。
- 能解释 CUDA 异步执行、Warmup、compute-only 与 end-to-end 的区别。
- 能手算 `H=[[2,3],[3,4]]`、`v=[1,-1]` 时 `Hv=[-1,-1]`、`v^T Hv=0`。
- 能判断包含 H2D 与只包含 `a @ b` 的结果边界不同，不能直接计算 GPU 加速比。

### 仍需订正

1. Parameter 与 Buffer 都可以注册并进入 `state_dict`，但只有 persistent Buffer 才默认进入 `state_dict`；running stats 只是 BatchNorm Buffer 的具体例子，不是保存容器。
2. `grad_fn` 表示产生当前 non-leaf Tensor 的 Autograd Function；`.grad` 保存累积到 Tensor 的梯度。
3. non-leaf 保留梯度的正确接口是 `retain_grad()`，不是 `contain_grad()`。
4. `retain_graph=True` 保留原图供再次 backward；`create_graph=True` 为导数计算建立新图，用于二阶导和 HVP。
5. 非标量 backward 的 `gradient` 是上游向量，Autograd 据此计算 VJP，而不是笼统的“该方向梯度”。
6. HVP 的可扩展性来自避免构造和保存 `[n,n]` 完整 Hessian，只计算指定方向上的 `Hv`；HVP 结果本身仍是长度为 `n` 的向量。
7. 方阵 MatMul 的近似计算量为 `2MNK`。`M=N=K=512` 时为 `268,435,456 FLOPs`，约 `0.268 GFLOPs`。

值得注意的是，Benchmark 代码已经正确计算了 `2 * size**3`，但闭卷时未能写出该公式，说明知识目前处于“能参考实现、不能稳定回忆”的阶段。

### 4.3 Multi-path 实验

实际运行结果：

```text
AttributeError: 'Tensor' object has no attribute 'contain_grad'
Did you mean: 'retain_grad'?
```

当前问题：

- 接口名应为 `retain_grad()`。
- 字段 `square_contibution` 存在拼写错误，应为 `square_contribution`。
- 即使对 `square` 和 `linear` 调用 `retain_grad()`，其 `.grad` 表示 `loss` 对这两个中间结果的梯度，都会是 `1`；它们不直接等于两条路径对 `x.grad` 的贡献 `4` 和 `3`。
- 如果要证明路径贡献，应分别计算 `d(x^2)/dx=4` 和 `d(3x)/dx=3`，再验证总梯度为 `7`。
