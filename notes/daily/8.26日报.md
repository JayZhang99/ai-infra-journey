### 3.3 必须订正的五个知识点

1. **VJP shape 链**

   ```text
   x in R^m
   y=f(x) in R^n
   J=dy/dx in R^(n x m)
   v in R^n
   v^T J in R^m
   ```

   PyTorch `autograd.grad(outputs=y, inputs=x, grad_outputs=v)` 的返回 shape 与 `x` 相同。

2. **完整 Jacobian 通常不构造**

   完整 Jacobian 有 `n*m` 个元素，时间和内存成本高；训练通常只需要 VJP，可以直接计算 `v^T J`。

3. **Profiler schedule**

   ```text
   WAIT: 不采集
   WARMUP: 启动采集系统，但丢弃结果
   ACTIVE: 正式记录
   RECORD_AND_SAVE: 完成周期并触发 on_trace_ready
   ```

4. **Observation 与 Hypothesis**

   Observation 是工具直接测得的事实；Hypothesis 是解释事实的待验证原因。一次 trace 中有空隙，不能直接写成“Profiler 就是原因”。

5. **Overlap 完整条件**

   pinned host memory、`non_blocking=True`、不同 CUDA Stream、无破坏流水的同步/依赖、硬件具备 copy/compute 并发能力需要同时检查。

### 4.1 公平 CPU/CUDA Benchmark

输入文件：

- `benchmarks/2026-08-26_wsl_cpu.json`
- `benchmarks/2026-08-26_wsl_cuda.json`
- `benchmarks/2026-08-26_compare.json`

共同协议：

```text
benchmark: square_matmul
boundary: matmul_compute_only
dtype: float32
warmup: 10
repeats: 100
PyTorch: 2.13.0+cu130
CPU threads: 8
GPU: RTX 4070 Ti
```

实测结果：

| Size | CPU median | CPU p95 | CUDA median | CUDA p95 | CPU/CUDA speedup |
|---:|---:|---:|---:|---:|---:|
| 128 | 0.014596 ms | 0.029264 ms | 0.018432 ms | 0.047211 ms | 0.79x |
| 512 | 0.648557 ms | 0.745637 ms | 0.027648 ms | 0.046798 ms | 23.46x |
| 1024 | 3.924368 ms | 3.989716 ms | 0.130368 ms | 0.151595 ms | 30.10x |

解释：

- 128 时 `speedup < 1`，CUDA 比 CPU 慢，说明小矩阵固定启动/调度成本无法摊薄。
- 512 与 1024 时 CUDA 分别快约 23.46x 与 30.10x。
- 该对比来自同一 WSL 环境，公平性明显高于此前 Mac CPU/WSL CUDA 的跨机器结果。
- speedup 只能归因于当前整套 CPU 路径与 CUDA 路径的差异，不能脱离硬件、库版本、线程数和算法选择写成普遍结论。

### 5.1 CPU Top 5

| 事件 | 次数 | Self CPU | CPU avg | 判断 |
|---|---:|---:|---:|---|
| `aten::mm` | 10 | 2.117 ms | 211.926 us | CPU 计算主体 |

CPU 路径中 `aten::mm` Self CPU 占 80.32%，说明当前 CPU 实验主要耗时在矩阵乘法本身。

### 5.2 CUDA Top 5

512×512 FP32、10 个 active steps：

| 事件 | 次数 | 平均 CUDA 时间 | CUDA 占比/含义 |
|---|---:|---:|---|
| CUTLASS GEMM Kernel | 10 | 17.643 us | 底层 Kernel 忙碌时间的 82.41% |
| split-K reduction Kernel | 10 | 3.765 us | 底层 Kernel 忙碌时间的 17.59% |
| `aten::mm` | 10 | 21.408 us | 两个底层 Kernel 的归因合计 |
| `matmul_compute_only` | 10 | 22.663 us | 业务 annotation 的 CUDA span |

核对：

```text
17.643 us + 3.765 us = 21.408 us
```

父级 annotation、ATen 算子和底层 Kernel 是同一段工作的不同归因层级，不能把百分比相加。`matmul_compute_only` 的 105.86% 不是 GPU utilization。

### 5.3 trace 直接事实

```text
aten::mm: 10
cudaLaunchKernelExC: 10
GPU Kernel: 20
Memcpy/H2D: 0
Kernel busy sum: 214.077 us
first-to-last Kernel envelope: 703.599 us
local envelope busy ratio: 30.43%
cudaDeviceSynchronize: 522.103 us
```

每次 MatMul 的 GPU 结构：

```text
aten::matmul
  -> aten::mm
     -> CUTLASS GEMM Kernel
     -> splitKreduce Kernel
```

19 个相邻 Kernel gap 中，大部分约 1.1-1.5 us；四个明显大 gap 约为：

```text
75.019 us
67.972 us
159.535 us
167.840 us
```

这里的 30.43% 只是本次短 trace 内第一个到最后一个 Kernel 之间的局部比例，不能写成整张 GPU 的长期 utilization。

### 5.4 与 CUDA Event 交叉检查

同一 WSL CUDA、size=512：

```text
CUDA Event median: 27.648 us
CUDA Event p95: 46.798 us
Profiler Kernel sum avg: 21.408 us
Profiler annotation avg: 22.663 us
```

Event median 与 Kernel sum 相差约 6.240 us。二者量级一致，但测量边界不同：Event 测同一 Stream 上两个 Event 之间的工作，Profiler Kernel time 归因到底层 Kernel；差值不能直接命名为“Profiler overhead”。

## 六、Observation、Hypothesis 与 Conclusion

### Observation

- 10 次 `aten::mm` 对应 20 个 GPU Kernel。
- CUTLASS 与 split-K 平均分别约 17.643 us 和 3.765 us。
- trace 中没有 Memcpy/H2D。
- trace 中出现四个 67-168 us 的大 gap。
- 末尾出现一次约 522 us 的 `cudaDeviceSynchronize`。
- schedule 重采后，之前约 3.095 ms 的首个 CUDA `aten::mm` CPU 异常值不再出现在 active 数据中；本次 `aten::mm` CPU 最大约 57.919 us。

### 当前获得支持的判断

- WAIT/WARMUP/ACTIVE schedule 有效隔离了 Profiler 首次采集初始化污染。
- 同一 WSL 的数据支持“小矩阵固定成本占比高、规模增大后 CUDA 优势显著”的规模效应。
- 当前边界是 compute-only，因为输入已在 CUDA 上且 trace 内没有 H2D。

### 当前 Hypothesis

> 大 gap 可能与 full Profiler/CUPTI 采集开销、CPU 提交节奏、WSL 调度或库内部执行策略有关。

状态：**pending**。单份 full trace 不能确定根因。

### 被拒绝或降级的说法

- “发现两个 Kernel，所以发生了两次 H2D”：错误；Kernel 与 Memcpy 是不同事件，当前 Memcpy 为 0。
- “Top 5 百分比超过 100%，说明 GPU 超负荷”：错误；这是嵌套归因，不能跨层级相加。
- “trace 有空隙，所以一定是 Python launch 不够快”：证据不足；CPU 已经提前提交多轮工作，仍需控制实验。
- “Profiler Kernel time 就是最终 latency”：错误；最终 median/p95 以独立 benchmark 为准。
