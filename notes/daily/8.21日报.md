### 错题订正

#### 1. Parameter 的核心是注册语义

`Parameter` 被赋给 `nn.Module` 属性后会自动注册，出现在 `model.parameters()` 和 `state_dict()` 中，优化器通常据此取得可训练权重。它与普通 Tensor 的关键区别不是“Parameter 一定变化”，因为参数是否更新还取决于是否交给优化器、是否产生梯度和学习率等条件。

#### 2. Buffer 与 Parameter

- Parameter 通常由 `backward()` 产生梯度，并由 `optimizer.step()` 更新。
- persistent Buffer 不在 `model.parameters()` 中，默认不由优化器更新，但会进入 `state_dict()` 并随 `Module.to(device)` 迁移。
- BatchNorm 的 `running_mean` 和 `running_var` 是典型 Buffer，由模块的前向逻辑更新。

#### 3. `eval()` 不会关闭 Autograd

`model.eval()` 递归切换 Module 的 `training` 标志，主要影响 Dropout 和 BatchNorm；它不会修改全局 grad mode，也不会修改 Parameter 的 `requires_grad`，因此不能代替 `no_grad()` 或 `inference_mode()`。

#### 4. `no_grad()` 与 `inference_mode()`

两者都会让作用域内的普通计算不建立反向传播图。`inference_mode()` 还关闭更多 view tracking、version counter 和 forward-mode AD 相关工作，限制更严格。纯推理通常使用 `model.eval()` 配合 `torch.inference_mode()`；如果结果还需要重新进入 Autograd，优先考虑 `no_grad()`。

#### 5. Forward 为什么保存中间 Tensor

Backward 的局部导数公式经常依赖前向值。例如 `y=x²` 的导数是 `2x`，Autograd 必须保存或重建反向传播所需的中间信息。Saved Tensor/activation 是训练显存的重要组成部分，并非只是为了调试。

#### 6. 动态计算图

每次 forward 都根据本轮实际执行的 Python 路径构建计算图，因此可以自然支持条件分支、循环和变长输入。Backward 只沿本轮真正执行过的路径传播。

#### 7. `grad_fn` 与 `.grad`

- `grad_fn` 表示产生非叶子 Tensor 的 Autograd Function，是反向图中的节点信息。
- `.grad` 保存累积到叶子 Tensor 的梯度；非叶子 Tensor 默认不保留 `.grad`，需要先调用 `retain_grad()`。

#### 8. 非标量 backward 与 VJP

非标量输出没有唯一的隐式标量梯度，因此要向 `backward()` 传入上游向量。Backward 实际计算 Vector-Jacobian Product，即 `vᵀJ`；可理解为先用上游向量对输出做标量组合，再对输入求梯度。

#### 9. `retain_graph` 与 `create_graph`

- `retain_graph=True`：第一次 backward 后保留原图，允许再次沿同一张图反向传播。
- `create_graph=True`：为导数计算本身建立新图，用于二阶导数、Hessian 和 Hessian-vector product。

#### 10. 原地操作与版本计数器

Backward 可能依赖 forward 保存的 Tensor。原地操作修改其数据后，version counter 会变化；Autograd 检测到版本不一致时会报错，从而避免静默产生错误梯度。

#### 11. `Module.to()` 与 `Tensor.to()`

`Module.to(device)` 会原地修改 Module，并返回同一个对象，不会复制出独立模型。Tensor 通常写成 `x = x.to(device)` 接收返回值；若 dtype/device 已满足要求，`Tensor.to()` 也可能返回原对象。

#### 12. 保存与加载的严格验收

保存训练后 `state_dict`，重新构造相同结构的模型并加载权重；两个模型都执行 `eval()`，在 `inference_mode()` 下处理同一固定输入，然后比较输出最大绝对误差，例如要求 `< 1e-6`。

### 1. `inspect_graph()`

构建最小计算图：


| 字段 | 结果 |
|---|---:|

### 2. `gradient_accumulation_demo()`

```text
第一次 backward: 4.0
第二次累积后:     8.0
清空为 None:      True
再次 backward:    4.0
```

这证明 `.grad` 默认按加法累积；执行 `w.grad = None` 后，下一次 backward 从空梯度重新开始。

### 3. `detach_demo()`

| 验收项 | 结果 |
|---|---:|
| detached `requires_grad` | `False` |
| detached `grad_fn` | `None` |

结论：`detach()` 只切断 Autograd 关系，不复制底层数据；需要独立副本时使用 `detach().clone()`。

## 七、今日关键收获

1. `eval()` 管理模块行为，grad mode 管理 Autograd；两者是两个独立维度。
2. `grad_fn` 描述 Tensor 如何产生，`.grad` 保存累积到叶子 Tensor 的梯度。
3. 非标量 backward 的本质是 VJP，而不是自动生成并保存完整 Jacobian。
4. `retain_graph` 解决复用原图，`create_graph` 解决对梯度继续求导。
5. `detach()` 不等于复制；共享 Storage 与 Autograd 关系必须分别判断。
6. “测试通过”还要检查断言是否真实约束行为，并继续补足边界和不变量。
