• 2. 解释 available、selected、supported、assigned 四层 Provider

状态。

​	available 表示设备哪些provider可用

​	selected 表示runtime 选择什么设备

​	supported 表示设备是否支持该算子

​	assigned 表示provider运行该算子

• 3. 区分 Session startup、steady-state run，以及为什么二者不能进

入同一 latency sample。

​	Session startup 是Session完整的启动流程

 	steady-state run 复用 Session startup 的run

​	不是每次run 都需要startup

• 4. 区分 TensorRT Engine、ExecutionContext 和 min/opt/max。

​	TensorRT Engine 是生成的标准的框架

​	ExecutionContext 是每次run可变的参数和输入

​	min 是最小优化

​	opt 是最优优化

​	max 是最大优化

• 5. 分别举例 intra-op 与 inter-op，解释 TinyFFN 为什么不一定适合

ORT_PARALLEL。

​	intra-op 是 输入并发线程数

​	inter-op 是session run 并发线程数

​	因为TinyFFN 线性操作且计算简单，多线程固定开销可能占比更大

• 6. 解释 cat/name/dur/provider/op_name，并说明 Profile dur 为

什么不是正式 latency。

​	cat : 类别

​	name : 类别名

​	dur: event 时间

​	provider : provider 名

​	op_name : 算子名

​	profile dur: 包括了profile的开销
